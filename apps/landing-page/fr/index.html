Le problème : des consignes qui divergent

Chaque dépôt finit par avoir sa propre copie des mêmes consignes : une pour Claude Code, une autre pour Copilot, une troisième pour Cursor. Elles divergent, personne ne les relit, et les bonnes pratiques restent coincées dans un seul dépôt.

Des copies partout

Les mêmes consignes collées dans N dépôts et M outils.

Une dérive silencieuse

Chaque copie évolue seule, et les pratiques de l'équipe ne sont plus cohérentes.

Aucune relecture

Des consignes qui pilotent vos agents changent sans que personne ne les valide.

Comment ça marche

Une bibliothèque de skills, un fichier de config, une commande.

1

Écrire une fois

Rédigez skills/<techno>/<nom>/SKILL.md : un frontmatter et les consignes.

2

Déclarer les technologies

Listez les technologies de chaque dépôt dans repos.json : nestjs, postgres, nextjs, vuejs, nx…

3

Rendre

Les skills sont traduits dans le format natif de chaque plateforme, uniquement pour les dépôts concernés.

4

Ouvrir les pull requests

Les changements arrivent en pull requests. Prévisualisez d'abord avec --dry-run.

Voyez ce que font vos agents

Un board kanban local suit les sessions Claude Code et GitHub Copilot CLI dans vos dépôts. Depuis celui-ci, le serveur AI Factory lance des agents dans des worktrees git dédiés à chaque thread, avec un centre de messages et une console terminal.

Pensé pour les équipes

Source de vérité relue

Les consignes vivent dans un seul dépôt et passent par la même revue que le code.

Traçable

Chaque changement arrive dans un dépôt par une pull request, avec historique et auteur.

Indépendant de l'outil

Changez ou mélangez les assistants sans réécrire vos pratiques.

Open source

Apache 2.0. La bibliothèque de skills et tous les paquets sont publiés sous le scope @lk.

Local par défaut

Le board et le serveur n'écoutent que sur l'interface loopback.

Testé

Chaque projet applique un seuil de couverture de 100 % en CI.

Démarrer

Nécessite Node.js et git dans votre PATH.

# installer la commande maggie, le board et le serveur
npm install -g @lk/maggie-board

# prévisualiser ce qui serait poussé, sans effet de bord
maggie sync --config repos.json --dry-run

# ouvrir le board et le serveur d'agents
maggie
