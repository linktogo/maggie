## What it does

This domain describes MyAsso's auto-entrepreneur (AE) workspace: income tracking, customer relationship management, task/calendar workflows, and a later training-case and compliance module. The 2026-03-02 design separates AE treasury from association accounting, AE contacts from association members, and AE tasks from association events. Training workflows extend that workspace by linking each formation case to an existing CRM contact.

The records place the original frontend in `apps/my-asso` and its standalone NestJS API in `apps/api-ae`. The formation plan and task list also refer to `apps/my-asso-frontend`; the supplied records do not establish whether that is a renamed app or a stale path. These are design and task records, not confirmation that the formation module or every deployment step is live.

## Architecture as designed

- **Treasury, CRM, and calendar frontend:** `/ae-treasury`, `/crm`, and `/ae-calendar` are separate surfaces enabled together by the `portal-auto-entrepreneur` feature toggle. Dedicated `AeTransaction`, `AeContact`, `AeOpportunity`, `AeTask`, and `AeConfig` contexts serve reactive client reads and CRUD through the Firestore Client SDK, subject to Firestore Security Rules. Shared types and Zod schemas are in `apps/my-asso/src/lib/data.ts`; the design also calls for export and task actions, navigation, onboarding, and four-locale UI strings.
- **AE records:** Tenant data uses `authGroupId` and `ae_`-prefixed records: `ae_transactions`, `ae_contacts` with an `interactions` subcollection, `ae_opportunities`, `ae_tasks`, `ae_config`, and `ae_user_preferences`. Transactions track the amount and payment progress; contacts are independent of members; opportunities form a configurable pipeline and can lead to a transaction; tasks hold due dates, reminders, recurrence, and completion state. `isPrivate` and `createdBy` provide an opt-in creator-only filter on otherwise tenant-shared records.
- **REST and scheduled operations:** The separate NestJS `api-ae` uses Firebase Admin, so it bypasses Firestore Security Rules. Its REST services must enforce tenant isolation themselves. `ApiKeyGuard` checks `X-API-Key` against `auth_groups.aeApiKey` and derives the tenant; cron routes use `CronSecretGuard` and `CRON_SECRET`. `/health` is public. Frontend contexts remain the CRUD path; Server Actions are reserved for exports and privileged operations. The API contracts describe transaction, contact, opportunity, task, config, and cron surfaces, but the supplied digest does not list exact route paths.
- **Training cases and documents:** AE Formation extends the AE contact and configuration model rather than replacing treasury or CRM. `FormationCase` is linked to an existing contact; participants are part of a case, not a separate entity. The proposed Firestore records are `ae_formation_cases`, `ae_formation_documents`, `ae_document_templates`, and tenant-shared `ae_watchlist`, with the existing `ae_config` extended. Templates and case data are tenant-scoped, and defaults are injected when a tenant has not configured a template. Client contexts provide real-time reads; `api-ae` and Admin SDK handle generation and generated-document writes, with Firebase Storage holding PDFs.
- **Formation generation and audit export:** Generate four separate PDFs from editable templates: quote, training agreement, program/modalities, and invoice. Invoice numbering is sequential per tenant in `{YYYY}-{NNNN}` form using an atomic increment of `ae_config.lastInvoiceNumber`. Audit export creates per-case folders and a year-summary CSV; it is blocked if any selected case lacks any of its four documents.
- **PDP transmission:** V1 is manual and uses `ManualPdpAdapter`, which returns `non_transmise`; a real provider adapter is V2 work and depends on selecting a PDP. The planned `IPdpAdapter` boundary maps provider transmission/status behavior into the module's status vocabulary. PDP credentials are stored and accessed through `api-ae`, encrypted, and masked in configuration responses. The research mentions `pdp_tokens/{authGroupId}` as a token-cache location but does not establish a selected provider or a delivered V2 token flow.

## Invariants

1. Scope AE business records and Firebase Storage paths by `authGroupId`. For tenant-shared records, include only records matching that tenant; when private mode is enabled, also restrict them by `createdBy`. Enforce this in both Firestore client queries/rules and every Admin-SDK service. **Source:** [`specs/027-tresorerie-crm-calendrier/data-model.md`](specs/027-tresorerie-crm-calendrier/data-model.md); [`specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md`](specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md); [`specs/030-module-ae-formation/spec/plan.md`](specs/030-module-ae-formation/spec/plan.md); [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md).
2. Keep AE transactions, contacts, and tasks distinct from association accounting transactions, members, and events. Link an opportunity to a contact and permit conversion to a transaction only when its stage is `gagne`. **Source:** [`specs/027-tresorerie-crm-calendrier/research.md`](specs/027-tresorerie-crm-calendrier/research.md); [`specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md`](specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md).
3. Keep transaction `amount` positive; constrain `amountPaid` to zero through the total amount. Preserve the three payment states and represent partial receipts with `amountPaid`, not a new payment status. **Source:** [`specs/027-tresorerie-crm-calendrier/data-model.md`](specs/027-tresorerie-crm-calendrier/data-model.md); [`specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md`](specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md).
4. Treat `portal-auto-entrepreneur` as the shared gate for the three spec 027 navigation entries. Keep UI text routed through `t()` in the four supported locales (French, English, German, and Spanish). **Source:** [`specs/027-tresorerie-crm-calendrier/plan.md`](specs/027-tresorerie-crm-calendrier/plan.md); [`specs/027-tresorerie-crm-calendrier/quickstart.md`](specs/027-tresorerie-crm-calendrier/quickstart.md).
5. Do not let Admin-SDK API or cron access rely on Firestore Security Rules: require the API key and tenant filtering for REST operations, and the cron secret for scheduled routes. **Source:** [`specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md`](specs/027-tresorerie-crm-calendrier/contracts/api-contracts.md); [`specs/027-tresorerie-crm-calendrier/quickstart.md`](specs/027-tresorerie-crm-calendrier/quickstart.md).
6. Preserve the case-state progression `en_cours` → `termine` → `cloture`; require a closing date. A closed case is read-only except for administrator actions explicitly allowed by the design; do not make reopening a normal member operation. **Source:** [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md); [`specs/030-module-ae-formation/spec/plan.md`](specs/030-module-ae-formation/spec/plan.md).
7. Generate the quote, training agreement, program/modalities document, and invoice as four distinct PDFs. Allocate invoice numbers atomically per tenant in `{YYYY}-{NNNN}` order using `ae_config.lastInvoiceNumber`. **Source:** [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md).
8. Keep generated-document writes on the `api-ae`/Admin-SDK path and store their PDFs in Firebase Storage; do not permit direct client writes to PDP credential fields. Mask the PDP API key in configuration responses and never log API keys, client secrets, or OAuth tokens. **Source:** [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md); [`specs/030-module-ae-formation/research/pdp-integration.md`](specs/030-module-ae-formation/research/pdp-integration.md).
9. Do not export an audit archive if any selected case lacks any one of its four generated documents. Keep the archive organized by case and include the year summary CSV; apply the specified year, status, and financing filters. **Source:** [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md).
10. Keep the watchlist shared within the tenant, not private to its creator. Do not add granular role-based permissions, electronic signatures, attendance sheets, learner portals, trainer scheduling, or bulk Excel import within the described formation scope. **Source:** [`specs/030-module-ae-formation/spec/spec.md`](specs/030-module-ae-formation/spec/spec.md).
11. Keep a real PDP provider adapter out of V1. Use the manual adapter/status until a provider is selected and V2 is deliberately implemented; map external statuses to the module's transmission vocabulary rather than exposing provider-specific values as domain states. **Source:** [`specs/030-module-ae-formation/research/pdp-integration.md`](specs/030-module-ae-formation/research/pdp-integration.md); [`specs/030-module-ae-formation/spec/plan.md`](specs/030-module-ae-formation/spec/plan.md).
12. Treat €77,700 / €188,700 as the documented 2024 French thresholds, not as automatically current legal values. The design says these figures require manual updates when necessary. **Source:** [`specs/027-tresorerie-crm-calendrier/spec.md`](specs/027-tresorerie-crm-calendrier/spec.md); [`specs/027-tresorerie-crm-calendrier/research.md`](specs/027-tresorerie-crm-calendrier/research.md).

## Drift and superseded decisions

This is the risky part of the document: these records include both a task list that marks spec 027 complete and a later formation plan that remains in planning. They describe intent and reported task status, not the current code, deployed rules, or production data. Verify those directly before changing behavior.

- The spec 027 task list marks T001–T061 complete, but the quickstart and plan describe deployment and testing steps without proving production deployment. Treat “complete” as the task record's claim; verify current routes, rules, indexes, feature toggle, and deployment before relying on them. **Sources:** [`specs/027-tresorerie-crm-calendrier/tasks.md`](specs/027-tresorerie-crm-calendrier/tasks.md); [`specs/027-tresorerie-crm-calendrier/quickstart.md`](specs/027-tresorerie-crm-calendrier/quickstart.md); [`specs/027-tresorerie-crm-calendrier/plan.md`](specs/027-tresorerie-crm-calendrier/plan.md).
