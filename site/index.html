The problem: instructions that drift

Every repository ends up with its own copy of the same agent instructions: one for Claude Code, another for Copilot, a third for Cursor. They diverge, nobody reviews them, and good practices stay stuck in one repo.

Copies everywhere

The same guidance pasted into N repositories and M tools.

Silent drift

Each copy is edited on its own, so the team's practices stop being consistent.

No review

Instructions that steer your agents change without anyone approving them.

How it works

One skill library, one config file, one command.

1

Author once

Write skills/<techno>/<name>/SKILL.md: frontmatter plus the guidance itself.

2

Declare technologies

List the technologies of each repo in repos.json: nestjs, postgres, nextjs, vuejs, nx…

3

Render

Skills are translated into each platform's native format, only for the repos that match.

4

Open pull requests

Changes land as pull requests. Preview first with --dry-run.

See what your agents are doing

A local kanban board tracks Claude Code and GitHub Copilot CLI sessions across your repositories. From it, the AI Factory server launches agents in per-thread git worktrees, with a message center and a terminal console.

Built for teams

Reviewed source of truth

Guidance lives in one repository and goes through the same review as code.

Traceable

Every change reaches a repo through a pull request, with history and an author.

Tool-agnostic

Switch or mix assistants without rewriting your practices.

Open source

Apache 2.0. The skills library and all packages are published under the @lk scope.

Local by default

The board and the server answer on the loopback interface only.

Tested

Every project enforces a 100% coverage gate in CI.

Get started

Requires Node.js and git on your PATH.

# install the maggie command, the board and the server
npm install -g @lk/maggie-board

# preview what would be pushed, no side effects
maggie sync --config repos.json --dry-run

# open the board and the agents server
maggie
