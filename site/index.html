The problem: instructions that drift

Every repository ends up with its own copy of the same agent instructions: one for Claude Code, another for Copilot, a third for Cursor. They diverge, nobody reviews them, and good practices stay stuck in one repo.

Copies everywhere

The same guidance pasted into N repositories and M tools.

Silent drift

Each copy is edited on its own, so the team's practices stop being consistent.

No review

Instructions that steer your agents change without anyone approving them.

How it works

One skill library, one config file, one command.

1

Author once

Write skills/<techno>/<name>/SKILL.md: frontmatter plus the guidance, with scripts and references next to it if needed.

2

Declare technologies

List the technologies of each repo in repos.json: nestjs, postgres, nextjs, vuejs, nx…

3

Render

Skills are translated into each platform's native format, only for the repos that match — including .agents/skills/ and an index in AGENTS.md that leaves your own text alone.

4

Open pull requests

Changes land as pull requests. Preview first with --dry-run.

Trust what reaches your agents

A skill runs with your agent's permissions in every repository it is synced to. maggie treats the library like a dependency.

Lint before sync

maggie lint checks the Agent Skills structure and scans for secrets, curl | sh, prompt injection and hidden Unicode. A library with errors is never synced.

Know what drifted

maggie sync --check compares every repository with the library, pushes nothing, and shows the missing, edited or stale files on the board.

Measure each skill

maggie eval runs a skill's cases with a real agent, without and with the skill, and reports the difference in pass rate.

More than Markdown

Scripts, references and assets ship with the skill, next to it where the tool supports folders.

See what your agents are doing

A local kanban board tracks Claude Code and GitHub Copilot CLI sessions across your repositories. From it, the AI Factory server launches agents in per-thread git worktrees, with a message center, a terminal console and one-click quick replies when the agent asks you to choose.

Built for teams

Reviewed source of truth

Guidance lives in one repository and goes through the same review as code.

Traceable

Every change reaches a repo through a pull request, with history and an author.

Tool-agnostic

Switch or mix assistants without rewriting your practices.

Open source

Apache 2.0. The skills library and all packages are published under the @linktogo scope.

Local by default

The board and the server answer on the loopback interface only.

Tested

Every project enforces a 100% coverage gate in CI.

Get started

Requires Node.js 24.22.1+ and git on your PATH.

# install the maggie command, the board and the server
npm install -g @linktogo/maggie-board

# preview what would be pushed, no side effects
maggie sync --config repos.json --dry-run

# scan the skills library, then see which repos drifted
maggie lint
maggie sync --config repos.json --check

# open the board and the agents server
maggie
